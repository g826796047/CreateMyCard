# L0 测试基线与目录规范

## 目标与边界

本轮只建设 L0 确定性业务测试，并为后续 L1 固定响应链路回放保留目录和 PR 流水线入口。
L0 不调用真实模型、生产数据、外部服务、浏览器或设备；允许使用进程内 HTTP/WebSocket 客户端、
临时文件和固定响应完成少量组件级合同测试。

本项目所称 L0 不等同于 Ruff 等静态代码分析。校验器、转换器、schema、注册表、协议、序列化等业务代码
即使跨越多个模块，只要使用固定输入、执行结果确定且没有外部依赖，也属于 L0 组件合同测试。
Ruff 与 `git diff --check` 作为独立的 Python 代码质量门禁运行，不计入 L0 测试数量。

L0 不能证明真实模型效果或真机显示质量。本规范只覆盖 `widget_service` 业务代码；
Debug Tools、浏览器截图和设备验收不在本轮修改范围内，继续沿用各自现有入口。

本轮收集基线仅统计 `widget_service/test/`。生产源码内仍有 93 个
`widget_service/cloud/services/template_generation/tests/test_*.py` 模块尚未被当前 PR 流水线收集，
其盘点、稳定性核对、CI 接入和后续迁移按 `docs/项目待整改清单.md` 的 P1-02 单独推进；在完成前，
不得把下述 L0 通过数量解释为模板测试也已通过。`debug_tools/tests/` 则按调试平台规范独立维护，
不迁入微服务测试目录。

## 新目录

```text
widget_service/test/
  README.md                    # 目录职责与常用入口
  conftest.py                  # pytest 公共夹具与分层标记
  level0/

    integration/             # 校验、转换、产物和进程内接口组件合同
  level1/

  smoke/                     # 真实模型生成与校验冒烟
  manual/
    live_ws/                 # 依赖人工启动服务的 WebSocket 联调
    load/                    # 不由 pytest 收集的人工压测脚本

  support/                   # 共享测试客户端与解析辅助代码
```

业务测试根目录不再平铺 `test_*.py`。现有文件按主要被测边界归入 unit 或 integration；主题图片、
每日计次、编辑和生成等互相复用固定样本的组件簇暂时保持在同一目录，避免测试间通过路径注入形成
隐式依赖。新增测试必须选择明确层级，`conftest.py` 会在收集阶段拒绝未归类文件。

当前收集基线为 9554 条：unit 5151 条、integration 4388 条、manual 15 条。PR 的 L0 入口执行前两类，
因此共运行 9539 条（其中基线包含 2 条条件性 skip），manual 不进入自动化通过率。

本轮按真实边界复核历史分类：错误投影与插件流出口、百炼传输与统一模型路由分别拆成 unit 和
integration；纯转换、纯校验规则、主题选择和协议资源测试迁回 unit。仍混合多个层级的大文件不为降低
数量而机械迁移，后续优先拆分 `test_service_units.py`、`test_compact_plan.py`、
`test_static_content_generation.py`、`test_single_step_generation.py` 和主题图片共享样本簇。

## 标记与准入

- `l0`：无真实模型和外部依赖的确定性测试。
- `l1`：固定模型响应的真实生产编排回放。
- `unit`：单个函数、类或模块范围的确定性单元测试。
- `integration`：多个确定性业务组件之间的公开合同测试。
- `manual`：依赖人工启动服务、设备、浏览器或其它外部环境。
- `model_smoke`：启动主服务并调用真实模型，验证生成结果及 DSL 校验；不计入 L0。

pytest 开启严格标记，拼写错误或未登记标记直接失败。L0 用例不得同时标记为 `manual`。

## 测试设计规则

1. 优先断言公开状态、结构化错误、最终产物和业务不变量，不断言私有函数调用顺序。
2. 不对完整 Prompt、完整 Trace、完整日志或大段 DSL 做默认快照；只验证目标字段和禁止字段。
3. 注册表和 schema 测试验证合同、合法/非法/边界样本，不复制一份生产规则到测试代码。
4. 修复类测试同时验证目标问题消失，以及无关内容、顺序、类型和 `None` 语义保持不变。
5. 进程内 FastAPI/TestClient 和固定传输 Stub 可作为 L0 组件合同；真实监听端口和远程调用不属于 L0。
6. 仅内部重构时不修改测试。合同变化时修改对应合同测试，并说明设计依据。

本轮已将生成响应序列化测试迁入 `level0/unit`，把完整字典相等改为稳定字段、内部字段隔离和
成功状态指令存在性的断言；组件合同放入 `level0/integration`，通过公开入口验证跨模块不变量。

## 本地与 CI 入口

```shell
# 主服务真实模型生成与 DSL 校验冒烟
python -m pytest widget_service/test/smoke/compact_dsl_smoke.py -q

# 微服务 L0
python -m pytest widget_service/test -m l0 -q -ra

# 当前手工执行 L1；暂不接入 PR 工作流
python -m pytest widget_service/test/level1 -m l1 -q -ra
```

PR 工作流只执行 Python 代码质量检查和微服务 L0，不调用真实模型，也不依赖模型凭据。
真实模型冒烟仅允许通过 `workflow_dispatch` 手工触发，并作为独立任务报告结果，不计入 L0 通过率。
冒烟测试使用 `test/support/` 内的微服务测试客户端，不反向依赖 `debug_tools` 的批跑实现。
L1 已落地首稿通过、单轮修复成功和修复预算耗尽三个固定响应回放场景；当前保留本地手工入口，
暂不接入 PR 流水线。后续决定接入时必须执行真实场景，不得以空任务通过。

全仓库仍存在早期 Python 目录的 Ruff 技术债，因此静态任务先对 PR 变更的 Python 文件执行 Ruff，
并对整个 PR 差异执行 `git diff --check`；这不会用新增门禁掩盖旧告警，也不要求本轮顺带重写无关代码。

## 后续 L1 接入约束

L1 使用生产编排、生产 Prompt Builder、生产校验器和临时 Artifact 存储，只在模型边界替换统一 Fake。
场景声明终态、各阶段逻辑调用次数、独立重试预算和必要/禁止 Trace 事件；固定输出夹具不保存第二套
校验结论。首批场景应覆盖首稿通过、warning 不修复、单轮修复成功、预算耗尽、不可重试失败和主备切换。
